# 010-G — ضغط قتالي متكرر مع تغطية قابلة للقياس

القاعدة main الأخضر 8cafea7fcf541009ff8ba9e49093f0b0bb9c949a. لا تعديل للنواة أو ضرر اللعبة أو VERSION/BUILD. بالإضافة للاختبارات وCI، يصحح hook تشخيصي بداية الدخول للعبة في العملية نفسها: لا تبقى علامة sessionEnded السابقة عند فتح جلسة لعب أخرى. هذه بيانات عرض تشخيصية فقط، وليست respawn أو mutation لحالة القتال.

يبقى وضع aging لساعتين من زمن المحاكاة وجولات ثابتة 120 ثانية، لاختبار التفاف السجلات وتقدم الحالة بعد سقوط اللاعب. يضاف وضع combat مستقل لساعتين من الزمن المحاكى: تنتهي جولة الاختبار عند عجز اللاعب الفعلي، وتبدأ جلسة اختبار جديدة عبر EngineCore::reset العام، دون تعديل الصحة أو منع الضرر أو إضافة respawn إلى اللعبة.

قبل كل reset يُفحص تطابق hash بين نسختي الاختبار وسلامة الحالة والسجل وعدم rollback. لا يمكن للـreset إخفاء فشل آخر slice. تبقى المدخلات عبر queue الأصلية، والمحاكاة 60Hz والسعات ثابتة. المقذوفات الاصطناعية فوق الخريطة توفر حمل CPU bounded حتى 96؛ لا ندّعي أنها تمثل المشهد البصري أو الاصطدامات الواقعية كلها. إطلاق AI وإصاباته للاعب يحدثان عبر المسار القتالي الحقيقي ويشترط الاختبار حدوثهما.

شرط نجاح combat: نسبة >=90% من خطوات الاختبار يكون فيها 31 AI قادرًا + اللاعب قادرًا، وبالتزامن >=64 مقذوفًا. تُطبع المدة الفعلية المتزامنة وعدد الجولات والإطلاقات والإصابات، لا الذروة وحدها. عد ordinary C++ new/new[] يجب أن يبقى صفرًا أثناء التنفيذ.

المدة تراكمية عبر جولات اختبار قصيرة، وليست جلسة قتالية متصلة بلا reset. كلا الوضعين إلزامي في CI؛ لا يحل أحدهما محل الآخر. لا تقيس هذه الاختبارات حرارة iPhone أو GPU أو FPS الحقيقي أو تسربات Swift/Metal، ولا تغلق hitch 1150ms. وضع الحفظ التشخيصي 010-F يظل مستقلًا عن اختبارات النواة هذه.
